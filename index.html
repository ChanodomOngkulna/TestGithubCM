คู่มือ Git
ดีไซน์ธีมสีถนอมสายตา (Warm Eyecare Palette)

Workflow การทำงาน 1 Repository ร่วมกันหลายคน

ป้องกันโค้ดพังด้วยกฎทอง: "ไม่ Push งานเข้า main โดยตรง" ให้สร้าง Branch แยกเสมอแล้วส่ง Pull Request ให้ทีมรีวิว

STEP 1

อัปเดตโค้ดล่าสุด

สลับไป main แล้ว pull โค้ดล่าสุดเพื่อนลงมาเสมอ

git pull origin main
STEP 2

สร้าง Branch ของคุณ

แตก Branch ย่อยเพื่อพัฒนาฟีเจอร์ของตนเอง

git checkout -b feature/name
STEP 3

Push ขึ้น GitHub

Commit งานในเครื่องแล้วส่งขึ้นระบบ

git push -u origin feature/name
STEP 4

สร้าง Pull Request

ส่งคำขอเข้า GitHub เพื่อตรวจและ Merge เข้า main

เปิดหน้าเว็บ GitHub.com

คลังคำสั่ง Git

18 คำสั่ง

ไม่พบคำสั่งที่ตรงกับคำค้นหา

ลองพิมพ์คำอื่น เช่น "merge", "reset", "revert" หรือกดล้างการค้นหา

การอ่านสัญลักษณ์ในไฟล์เมื่อเกิด Merge Conflict

VS Code จะไฮไลต์ส่วนที่โค้ดชนกันให้เห็นชัดเจนดังตัวอย่างนี้:

// ส่วนโค้ดในเครื่องของคุณ (Current Change)
<<<<<<< HEAD
const apiUrl = "https://api.myproject.com/v1";
======= (เส้นแบ่งกลางระหว่างสองเวอร์ชัน)
// ส่วนโค้ดของเพื่อนที่ถูก push ขึ้นมาล่าสุด (Incoming Change)
const apiUrl = "https://api-v2.myproject.com/v2";
>>>>>>> origin/main
1. ตัดสินใจเลือกรักษาโค้ด เลือกกดปุ่ม Accept Current (ของตนเอง) หรือ Accept Incoming (ของเพื่อน) หรือแก้ผสมกัน
2. ลบสัญลักษณ์ส่วนเกิน ลบบรรทัดเครื่องหมาย <<<<<<<, =======, >>>>>>> ออกให้หมด
3. Commit จบงาน เซฟไฟล์ แล้วใช้คำสั่ง git add . ตามด้วย git commit เพื่อจบกระบวนการ

คัดลอกคำสั่งเรียบร้อยแล้ว!
